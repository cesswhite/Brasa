# Seguridad

No publiques credenciales, datos de cuentas ni instrucciones de explotación contra servicios activos en una issue pública. Usa el reporte privado de vulnerabilidades de la pestaña Security cuando esté habilitado; si no aparece, solicita un canal privado al mantenedor sin incluir el hallazgo sensible.

El repositorio contiene referencias históricas a un staging real. La publicación del código no concede autorización para pruebas de carga, acceso a cuentas ajenas, migraciones o despliegues sobre él. Reproduce hallazgos en una base local aislada o en tu entorno autorizado.

Los secretos se mantienen fuera de Git. Si una credencial se filtra, revócala/rotála primero; borrar el archivo del commit actual no elimina copias o historial. No imprimas tokens de sesión en reportes.

No se promete un plazo de respuesta ni una auditoría completa de seguridad. Los informes de pruebas describen su fecha y revisión.
